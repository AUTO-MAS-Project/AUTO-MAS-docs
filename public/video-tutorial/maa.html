AUTO-MAS 部署 MAA（明日方舟）脚本图文教程

本文根据 2026-09-17 的完整部署录屏 2026-09-17 16-01-16.mp4（96 分钟，1920×1080）逐步整理而成，覆盖从下载安装包到 MAA（明日方舟）脚本配置完成并成功自动执行的全流程。 所有截图均取自实际部署过程，红圈 / 红框标注的就是该步骤中鼠标点击（或双击）的位置。

  • 软件版本：AUTO-MAS v5.4.0，MAA v6.17.5，MuMu 模拟器 12
  • 自动化链路：AUTO-MAS（脚本管理 / 调度）→ MAA（游戏自动化本体）→ MuMu 模拟器中的明日方舟

1. 准备工作

1.1 需要提前下载的文件

在浏览器中下载以下 2 个压缩包（本例均保存在 E:\Badwolf\Downloads，即资源管理器里的「下载」文件夹）：

文件 作用 大小（约）
AUTO_MAS-v5.4.0.zip AUTO-MAS 主程序安装包（内含 AUTO-MAS-Setup.exe） 155 MB
MAA-v6.17.5-win-x64.zip MAA 明日方舟脚本 260 MB

截图中还有 MaaEnd-v2.28.0-win-x86_64.zip，那是《MaaEnd（终末地）脚本教程》使用的，部署 MAA 不需要它。

1.2 环境前置条件

  • 解压工具：系统需能解压 .zip（视频中使用 WinRAR 查看压缩包，解压用的是 Windows 自带的「全部解压缩」，两者任选）。
  • MuMu 模拟器 12 已安装（本例安装于 E:\Games\MuMuPlayer），并且模拟器里已安装、登录《明日方舟》。
  • 磁盘空间：AUTO-MAS 安装至少需要 588.8 MB 可用空间，另为 MAA 预留约 1.5 GB。

💡 目录约定：本教程将 AUTO-MAS 装到 D:\AUTO-MAS，MAA 解压到 D:\MAS 下。路径中尽量不要出现中文和空格，可减少后续抓窗口、ADB 连接类问题。

2. 安装 AUTO-MAS 主程序

2.1 解压安装包

  1. 在「下载」文件夹中右键单击 AUTO_MAS-v5.4.0.zip。
  2. 选择 「全部解压缩」。
  3. 目标路径保持默认（自动填为 …\Downloads\AUTO_MAS-v5.4.0），单击「提取」。
  4. 解压完成后进入该文件夹，可以看到 AUTO-MAS-Setup.exe（约 159,699 KB）。

2.2 运行安装向导

双击 AUTO-MAS-Setup.exe：

  1. 选择安装语言：保持「简体中文」，单击「确定」。

  2. 许可协议：阅读 GNU AGPLv3 协议，点选「我同意此协议」，然后单击「下一步」。

  3. 选择目标位置：默认是 C:\Program Files\AUTO-MAS。本例通过「浏览」改为 D:\AUTO-MAS（也可以直接在输入框中改），单击「下一步」。

  4. 正在安装：等待安装程序解压文件（进度条走完，期间会显示 D:\AUTO-MAS\AUTO-MAS.exe 等文件名）。

  5. 安装完成：保持勾选 「运行 AUTO-MAS」，单击「完成」。安装程序退出并自动启动 AUTO-MAS，桌面上也会生成 AUTO-MAS 快捷方式。

3. 解压 MAA 脚本并整理目录

  1. 右键单击 MAA-v6.17.5-win-x64.zip，在右键菜单中选择 「全部解压缩...」：

  2. 目标路径默认为 …\Downloads\MAA-v6.17.5-win-x64，单击「提取」（「完成时显示提取的文件」可勾可不勾）。

  3. MAA 包含 1 万多个文件，解压需要几分钟，耐心等待。

  4. 解压完成后，建议把 MAA-v6.17.5-win-x64 文件夹剪切到统一的目录（本例为 D:\MAS），后续配置时更清晰、路径更短：

4. 首次启动：自动配置运行环境

首次启动 AUTO-MAS 会弹出环境配置向导「欢迎使用 AUTO-MAS，正在自动配置您的运行环境」，共 6 步，全程自动，无需任何点击：

步骤 内容 说明
1 Python 安装 安装内置 Python 完成后显示「Python 安装完成 / 环境已就绪」
2 Pip 安装 安装 pip 自动
3 Git 安装 安装 Git 自动
4 源码拉取 克隆 AUTO-MAS 后端源码 自动切换镜像源（如 gh-proxy (Cloudflare)，尝试进度 1/7）
5 依赖安装 pip 安装依赖包 走国内镜像（如阿里云，尝试进度 1/4），耗时最长，耐心等待
6 后端启动 启动后端服务 见下方防火墙放行

4.1 允许 Python 通过防火墙（重要）

进入「后端启动」步骤时，会弹出 Windows 安全中心警报：

Windows Defender 防火墙已阻止此应用的某些功能。 名称：Python　路径：D:\auto-mas\environment\python\python.exe

单击「允许访问(A)」（默认已勾选「专用网络」，保持即可）：

4.2 进入主界面

随后显示「后端启动成功，应用已准备就绪，即将进入主界面」，自动进入 AUTO-MAS 主页：

主页左侧导航栏从上到下依次是：主页、脚本管理、计划管理、模拟器管理、调度队列、调度中心（底部还有游戏签到、历史记录、工具、设置）：

5. 导入模拟器（MuMu）

  1. 单击左侧导航 「模拟器管理」（上图红圈位置）。

  2. 单击右上角「🔍 自动搜索模拟器」：

  3. 稍等片刻，页面顶部会依次弹出「找到 1 个模拟器」「导入成功」，并自动生成 MuMu 配置：

    • 模拟器名称：MuMu模拟器
    • 模拟器类型：MuMu模拟器
    • 模拟器路径：E:/Games/MuMuPlayer/nx_main/MuMuManager.exe
    • 最大等待时间：300
    • 强力关闭：关

💡 如果自动搜索没有找到，可改用「+ 手动添加模拟器」，把路径手动指到 MuMu 安装目录下的 MuMuManager.exe。

6. 新建并配置 MAA 脚本

6.1 新建脚本

  1. 单击左侧导航 「脚本管理」（当前为空，显示 NO DATA）。
  2. 单击右上角「+ 新建脚本」。

  3. 在弹出的「新建脚本」窗口中点选「MAA 脚本」（明日方舟自动化与多账号日常代理），然后单击「创建并配置」：

脚本类型参考：通用脚本（具备日志文件的自动化脚本）、SRC 脚本（星穹铁道）、MaaEnd 脚本（MaaFramework 专项适配，见终末地教程）、M9A 脚本（重返未来：1999）、ok-ww / ok-nte / HSR 脚本等。

6.2 填写 MAA 脚本配置

进入「MAA脚本配置」页面：

页面顶部「使用说明」提示：剿灭任务会独立启动一次 MAA；MAA 专项仅支持模拟器，PC 版请使用通用脚本。

  1. 基本信息：

    • 脚本名称：默认「新 MAA 脚本」，可自行修改。
    • MAA路径：单击「选择文件夹」。

  2. 在文件夹选择窗口中，进入 MAA 解压目录（本例为 此电脑 > 软件 (D:) > MAS > MAA-v6.17.5-win-x64，目录内应能看到 MAA.exe），单击「选择文件夹」确认：

  3. 模拟器管理：

    • 模拟器：下拉选择「MuMu模拟器」。
    • 模拟器实例：选择要使用的实例（多开时按序号选择，单开选默认实例）。

  4. 运行配置（可保持默认）：

    • 账号切换方法：重启模拟器
    • 用户单日代理次数上限：0（不限制）
    • 剿灭代理超时限制（分钟）：40
    • 日常代理超时限制（分钟）：10
    • 代理重试次数限制：3

  5. 确认无误后保存。保存成功后脚本管理中会出现「MAA 脚本」卡片。

7. 配置 MAA 本体（连接与任务）

7.1 打开 MAA 配置

在「MAA 脚本」卡片上单击「配置 MAA」（或编辑脚本页中的配置入口）。AUTO-MAS 会提示「已启动 MAA 脚本的 MAA 配置」，同时页面被锁定，并弹出提示：

正在进行MAA配置 —— 当前正在配置MAA脚本，请在MAA配置界面完成相关设置。配置完成后，请点击"保存配置"按钮来解除页面锁定。

7.2 MAA 首次启动的防火墙放行

MAA 启动并尝试连接模拟器时，会再弹出一次 Windows 安全中心警报，这次是 adb.exe（路径 E:\games\mumuplayer\nx_main\adb.exe），同样单击「允许访问(A)」。

7.3 检查连接设置

在 MAA 窗口中进入 「设置 → 连接设置」，确认以下内容（使用「MuMu 模拟器」连接配置时会自动填充）：

  • 连接配置：MuMu 模拟器
  • 连接地址：127.0.0.1:16384（MuMu 12 默认 ADB 端口）
  • ADB 路径：E:\Games\MuMuPlayer\nx_main\adb.exe
  • 启用 MuMu 后端截图：勾选（MuMu 6.3.2+ 支持）
  • 触控模式：Minitouch（默认）

💡 若提示连接失败：先手动启动一次 MuMu 模拟器，再回到 MAA 点击重试；确认模拟器未选错「多开」实例、后台 ADB 已开启。

7.4 检查任务与启动设置

  1. 回到 MAA 的 「一键长草」 页面，按需勾选任务（开始唤醒、理智作战、基建换班、领取奖励等），不要点击 Link Start!——执行由 AUTO-MAS 调度负责：

  2. 进入 「设置 → 启动设置」，取消勾选「开机自启动」（自动启停交给 AUTO-MAS 管理，避免重复拉起）。

  3. 配置完成后关闭 MAA 窗口，回到 AUTO-MAS 锁定提示框，单击「保存配置」解除页面锁定（见 7.1 的截图，红圈即「保存配置」按钮位置）。

8. 添加 MAA 用户

  1. 在「MAA 脚本」卡片上单击「添加用户」，进入用户编辑页：

  2. 基本信息（红框区域开始逐项填写）：

    • 用户名称：自定义，如「鹰角你没有心」；
    • 账号ID：填 MAA 账号切换可识别的唯一片段（官服可只填手机号后几位）；
    • 启用状态：是；
    • 密码：可留空（仅用于存储以防遗忘，此外无任何作用）；
    • 服务器：官服（按实际选择）；
    • 剩余天数：-1（不限制）；
    • 用户配置模式：简洁（沿用 MAA 全局设置；需要精细控制时选「详细」）；
    • 基建模式：常规模式。

  3. 关卡配置：

    • 剿灭代理：当前剿灭；
    • 关卡配置模式：固定（也可选按星期轮换并在「每周计划」里编排）；
    • 其余代理关卡、次数按需设置。

  4. 任务配置：勾选该用户要执行的任务（开始唤醒、刷理智、剿灭模式、领取奖励等）。

  5. 保存后回到脚本管理，用户会出现在 MAA 脚本卡片下，并显示「配置已完成 / 配置已保存」提示：

9. 创建调度队列并试运行

9.1 新建队列

  1. 单击左侧导航 「调度队列」。

  2. 单击「新队列」创建一个队列（本例保持默认名「新队列」）：

  3. 队列参数：启动时运行＝否（AUTO-MAS 启动时不自动跑）；定时运行＝是；完成后操作＝无操作（也可选关机/休眠等）。

  4. 定时表：单击「添加定时」，设置执行周期（周一～周日）与执行时间（本例建了 3 条每日 00:00 的定时）。
  5. 任务列表：单击「添加任务」，把「MAA 脚本」加入队列，保存。

9.2 手动试运行

  1. 单击左侧导航 「调度中心」。

  2. 在「主调度台」选择要执行的任务（脚本 - MAA - MAA 脚本）与模式（自动代理），单击「开始执行」：

  3. 任务总览中可以看到 MAA 脚本 (1个用户) 进入「运行」状态，右侧日志开始滚动，第一条通常是「正在启动模拟器」：

  4. 全程自动完成：拉起 MuMu 模拟器 → 启动明日方舟 → MAA 连接（官服，127.0.0.1:16384）→ 执行开始唤醒 / 剿灭 / 日常代理 → 结算。日志中可看到 MAA 的完整输出（Bootstrapper、AsstProxy 等）：

  5. 运行结束后，任务总览显示「完成」，MAA 会弹出「即将自动关闭」并自行退出；若中途手动干预，可单击「停止任务」。

✅ 到这里，MAA 的「部署 + 验证」已经闭环，之后每天由定时队列自动执行。

10. 日常使用与定时调度

  • 手动执行：调度中心 → 选择任务（脚本 - MAA - MAA 脚本）与模式（自动代理）→ 「开始执行」。右上角可设置「任务完成后电源操作」（无动作 / 关机 / 休眠）。
  • 定时执行：由「调度队列」里的定时表驱动（本例每天 00:00 三条定时），到点自动跑完队列内所有任务。
  • 运行观察：调度中心右侧「日志」实时滚动执行日志，可勾选「保持最新」自动跟随；「历史记录」可回溯每次执行结果。
  • 修改任务内容：MAA 的任务勾选在 MAA 界面中调整；用户维度的覆盖配置在 AUTO-MAS 的用户编辑页。

11. 常见问题与注意事项

现象 处理
防火墙弹窗（Python / adb.exe） 均单击「允许访问」；MAA 部署过程一般出现 2 次
环境配置某一步失败 向导会自动切换镜像源重试（Git 源最多 7 次、pip 源最多 4 次）；多次失败请检查网络/代理后重开 AUTO-MAS
MAA 提示连接失败 / 截图失败 确认 MuMu 模拟器 12 已安装且能手动启动；连接设置用「MuMu 模拟器」预设（127.0.0.1:16384）；勾选「启用 MuMu 后端截图」；防火墙已放行 adb.exe
MAA 提示「检测到资源更新」 直接让 MAA 自动更新完成后再执行任务；更新期间勿关闭
脚本路径报错 确认选择的是包含 MAA.exe 的那一层目录；路径建议全英文
剿灭与日常的关系 剿灭任务会独立启动一次 MAA 单独执行；日常代理超时 10 分钟、剿灭 40 分钟，超时后按重试次数限制重试
B 服账号切换识别率低 账号ID 只填不易识别错误的唯一片段（避免生僻字、下划线），官服填手机号后几位即可
