# 配置语义

AUTO-MAS 的配置体系由两层构成：**base（基础配置）** 与 **overlay（覆盖层）**。任务运行期的生效配置是两层叠加的结果。本文定义这两层的标准术语，以及各配置来源的准确含义。

历史文案中的「脚本级 / 用户级 / 直控 / 快速配置」四词正在按本文统一。新代码、新文案与新文档一律使用本文术语。

## 运行期配置模型

```
任务运行期生效配置 = base ⊕ overlay
                        （overlay 优先生效）

┌─ overlay 层 ──── 任务期存在 · 优先级最高 · 结束恢复原 base ─┐
└──────────────────────────────────────────────────────────┘
┌─ base 层 ─────── 磁盘持久 · 来源三态（三选一）────────────┐
│          共享          │        独立        │     原生    │
└──────────────────────────────────────────────────────────┘
```

## base：基础配置

**base（基础配置）** 是任务运行时的主配置，磁盘持久、跨任务长期存在，来源为下列三态之一。

| 术语 | 原称 | 定义 | 磁盘 owner |
| --- | --- | --- | --- |
| **共享** | 脚本级 | base 存放在条目侧，该条目下多个账号共用同一份 base | 条目 |
| **独立** | 用户级 | base 存放在账号目录，单账号独有 | 账号 |
| **原生** | 直控 | base 即外部脚本自带配置，MAS 不维护、不建平行模型 | 外部脚本 |

### 三态的共同边界

三态只决定 base 的**磁盘 owner**，不承诺运行期最终生效一致：每个账号都可独立启用 overlay，任务期间的实际生效配置因人而异。

因此「共享」仅描述 base 层文件的多账号共用，**不等于**「改一处全员生效」——其他账号若启用了各自的 overlay，其运行期配置不会被这次改动完全覆盖。

## overlay：覆盖层

**overlay** 是任务运行期薄覆盖在 base 之上的配置层。

- **优先级**：高于 base，覆盖 base 的对应字段。
- **不改写来源**：虽绑定在账号设置页，但不对配置来源（base 三态）做任何改写。
- **结束恢复**：任务前覆写 base，任务结束后正确恢复原始 base；快照机制覆盖成功、失败、取消、超时、异常与崩溃全部路径。
- **可组合**：可与任意 base 来源组合，构成 3×2 矩阵。

| base 来源 | 无 overlay | 有 overlay |
| --- | --- | --- |
| 共享 | 直接使用共享 base | 共享 base ＋ 账号 overlay |
| 独立 | 直接使用独立 base | 独立 base ＋ 账号 overlay |
| 原生 | 直接使用脚本原生配置 | 原生配置 ＋ MAS 托管字段覆盖 |

::: warning 术语译名待定

以下术语尚未定稿。代码、文案与文档暂按现称保留，**新代码不要基于现称新增语义**，定稿后统一替换。

1. **脚本条目名**（MAS 内「新建脚本」产生的条目）：候选「托管」「实例」。
2. **账号条目名**（条目下的游戏账号，原称「用户」）：候选「账号」。
3. **快速配置面板名**：候选「高级」「优先」。
4. **overlay 译名**：候选「覆盖层」「优先层」；与第 3 项是否统一取「优先」待定。

:::

| 现术语 | 目标术语 | 语言用例（现 → 目标） |
| --- | --- | --- |
| 脚本级 | 共享 | 「使用脚本级共享配置，所有用户共用」→「使用共享基础配置，条目下所有账号共用」 |
| 用户级 | 独立 | 「配置用户级 MaaEnd」→「配置独立基础配置」 |
| 直控 | 原生 | 「脚本直控默认直接使用 SRA 当前保存的配置运行」→「原生配置默认直接使用 SRA 当前保存的配置运行」 |
| 脚本直控 | （整体消失） | 直控改名原生后，该词组不再保留，统一表述为「原生配置」 |
| 快速配置 | 待定（高级 / 优先） | 「使用下方快速配置面板中的高频任务字段覆盖当前脚本配置」→「使用下方〔待定〕面板中的高频任务字段覆盖当前脚本配置」 |

## zzz-od 的特殊性

zzz-od 无法按通用模型单例化：它是**单条目（单程序）多账号**结构，且「账号条目」与「上游实例（=账号）」是两层概念——每个条目仅允许一个原生来源账号，多账号在该账号的实例管理中配置。

因此：

- 「实例」若作为脚本条目名，将与 zzz-od 上游「实例」（=账号）冲突。
- base 三态在 zzz-od 的物理落点与标准专项不同（实例视图同在一份脚本级配置里）。
- zzz-od 的术语需单独讨论，**不套用本文的通用结论**。

## 落地范围

术语定稿后需要同步的范围：

- 前端 UI 文案与 i18n（`frontend/src/locales/zh-CN.ts`）
- 后端 schema 描述与配置注释（`app/models/schema.py`、`app/models/config.py`）
- 前端 OpenAPI 生成类型注释（**禁止手改**，需重新生成）
- `Info.Mode` 存储值（`"脚本"` / `"用户"` / `"直控"`）：如随术语改名需兼容迁移（已有「简洁/详细/自定义」→「脚本/用户/直控」先例）
- 专项适配代码中的硬编码比较（如 `== "直控"`）
- 本文档与仓库内术语表
