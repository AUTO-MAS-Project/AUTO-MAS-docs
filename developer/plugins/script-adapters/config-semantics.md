# 专项配置语义

接管上游脚本配置的专项，可以为一次任务选取基础配置，再应用当前账号的临时覆盖。覆盖字段优先，其余字段来自基础配置。本页约定的是专项的运行配置，[配置框架](../../core/config.md)负责主程序配置节点的暂存与持久化。

## 托管与账号

- **托管**：MAS 中管理外部脚本的配置实体，保存路径、启动参数与托管级设置，下属一个或多个账号。
- **账号**：托管下的执行配置，可保存游戏账户、凭据和任务设置。切换游戏账号的能力由专项提供。
- **代码标识**：现有代码与 API 保留 `Script`、`User`、`script_id`、`user_id` 等名称。页面和开发说明使用“托管”和“账号”，涉及上游对象时沿用上游称呼。

## 基础层

基础层（`base`）是跨任务保留的基础配置。支持哪些来源由专项决定，三种来源各自指定一份配置及其归属：

- **托管级（共享配置）**：基础配置属于托管。使用这一来源的账号共用同一份配置。
- **账号级（独立配置）**：基础配置属于当前账号。每个账号使用自己的配置。
- **原生**：基础配置属于上游脚本。专项使用其已有配置，持久修改通过上游配置入口保存。

## 覆盖层

覆盖层（`overlay`）是当前账号通过“覆写常规配置”提供的运行期设置。开启后只覆盖专项明确支持的字段。覆盖持续到本次任务结束，基础配置来源保持原值。同一托管中的其他账号仍按各自的来源和覆盖设置解析配置。

## 运行时如何应用配置

1. **定位基础配置**：读取账号所选来源，由专项找到对应的托管、账号或原生配置。
2. **准备覆盖字段**：如果支持并开启“覆写常规配置”，读取当前账号的有效覆盖字段。涉及文件写入时先准备恢复所需数据。
3. **执行脚本**：按字段应用覆盖值，使用本次生效配置调用上游运行入口。
4. **恢复基础配置**：在成功、失败、取消、超时和异常收尾路径中恢复临时改动，清理本次覆盖状态。进程崩溃后也应能用保留的恢复信息还原。

## 专项适用边界

先看专项的界面和运行代码，再解释其中的配置字段。下列专项使用自己的配置来源或覆盖规则：

- **MFW 及其风味**：读取账号任务快照，启动时使用[快照与运行计划](./mfw/run.md)。`Info.Base` 和 `Info.IfQuickConfig` 不参与配置选择。
- **General**：原生来源使用外部脚本配置，非原生来源使用当前账号的 `ConfigFile`。运行时不读取共享 `Default` 或覆写开关。
- **BetterGI**：提供账号级独立配置和原生配置。
- **HSR**：基础配置来自共享计划、账号计划或上游原生配置。运行时不创建账号 `ConfigFile` 副本，也不读取 `Info.IfQuickConfig`。
- **BAAH**：使用账号绑定的 `Info.ConfigName`。模拟器等托管项、关卡计划和活动优先分别按专项实现生效。
- **奇想盒**：`shared` 和 `independent` 均读取当前账号页面的设置。原生来源仅在启用覆写时临时写入面板覆盖字段，并在结束后恢复。

### zzz-od 的配置归属

MAS 账号绑定上游配置的实例槽。一个托管关联的原生配置树中，同时包含按实例槽保存与跨实例槽共享的内容。

1. **选择来源**：界面提供账号级独立配置与原生配置。使用独立配置时，按当前账号字段和绑定槽准备本次运行。
2. **确定备份位置**：备份按绑定槽分别保存，以便恢复对应实例的原始内容。
3. **运行原生配置**：脚本读取原生配置。`Info.IfQuickConfig` 与 MAS 任务覆盖不参与运行。

配置术语与统一过程见 [AUTO-MAS#879](https://github.com/AUTO-MAS-Project/AUTO-MAS/issues/879)。
