# 脚本专项适配

脚本专项把外部脚本的公开运行入口接入 AUTO-MAS。宿主负责托管、账号和调度，适配器提供配置声明、任务展开与脚本调用。先确定适配方式和能力归属，再修改对应配置、运行入口与页面。

## 选择适配方式

- **独立专项适配**：上游有自己的运行入口、配置和分发，例如 MAA 和奇想盒。后端由[独立专项插件](./standalone.md)提供，专项页面随主程序构建。
- **主程序内置专项**：需要维护现存内置类型时，从[配置、注册和调度](#主程序内置专项)查找实现。
- **MFW 风味专项**：上游是基于 MaaFramework 项目接口的脚本，通用 MFW 已覆盖导入和执行，专项只需补充个别能力。接入见[风味专项开发](./mfw/develop.md)。

## 确定适配边界

1. **明确用户操作**：先找可省去的手工步骤，例如导入、路径选择、初次配置或例行任务编排。记录上游的启动入口、配置归属、结果来源和发行物，再选用最接近的现有专项作为参考。
2. **使用上游契约**：游戏内操作、脚本执行与成败、脚本配置语义由上游负责。复用上游 CLI、公开 API、原生配置界面以及公开的退出码、日志或报告。私有配置、队列、记录和资源格式只做透传。
3. **实现 MAS 能力**：适配器可接入托管与账号管理、调度、计划表、通知、统计、模拟器生命周期和跨脚本编排。调度状态依据 MAS 实际观察的操作与上游公开结果记录。
4. **处理缺少的入口**：上游领域缺少入口时先评估向上游提 PR。上游不受理或审核与发布周期过长时，确有必要的临时实现须标明移除条件。上游提供对应能力后，改为调用上游入口，清理临时实现、配置和界面。

具体判据见主程序仓库 `.agents/skills/mas-script-specialized-adapter/references/blackbox-boundary.md`。

## 主程序内置专项

1. **找到类型注册**：从 `app/task/builtin_registration.py` 和对应的 `app/task/<专项>/registration.py` 查找类型声明。先看最接近的架构，例如 SRC、MaaEnd、General 或 ok-script 家族。
2. **接入配置与页面**：在托管和账号配置中明确字段的所有者和用途；配置生效规则见[专项配置语义](./config-semantics.md)。同时检查新建入口、编辑页面和路由。后端 Schema 变更后按[前端开发](../../core/api.md)重新生成接口定义。
3. **实现执行与收尾**：在对应任务模块中实现账号展开、启动、结果收集与收尾。临时写入的设置需在正常结束及异常路径恢复，进程和文件的清理分别处理。各级任务的责任见[调度逻辑](../../core/scheduling.md)。
4. **验证完整流程**：从正常入口创建托管和账号，再发起专项支持的运行模式。核对检查提示、任务日志、挂起或取消后的收尾，以及历史结果。
