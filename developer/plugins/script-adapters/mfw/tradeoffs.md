# MFW 设计取舍

MFW 以每个托管的独立视图隔离项目状态，以项目和更新渠道协调版本。以下约束用于维护导入、更新、运行与风味扩展。调整这些行为时，在变更说明中给出要解决的问题及受影响的场景。

## 导入、副本与投影

- **运行视图**：每个托管使用自己的目录，目录名取托管 UID 的前 12 位，降低 Windows 下嵌套路径超长的概率。导入后账号和任务都使用这棵视图，来源目录仍由用户管理。相关实现见 `embedded_project.resolve_maafw_project_root()`。
- **共享文件**：载荷和视图只为符合规则的文件建立硬链接。对可能写入的内容保留私有副本，对已经发生的写穿在运行收尾时巡检。共用文件保持可替换和可回收。相关实现见 `projection.is_shared_path()` 和 `view_audit.py`。
- **文件投影**：项目声明的资源和依赖优先保留，另保留可能被 agent 在运行时读取的部分未声明文件。可确认的外壳程序及其运行库才按规则剔除，项目自带的 Python 与 MaaFramework 库保留。规则见[导入与载荷视图](./import-and-payload.md)。

## 版本同步与更新

- **一致的组版本**：同一谱系和渠道使用同一个已登记版本。“不更新”表示该托管不主动联网查找；组版本推进时仍会同步。切回稳定渠道等操作可切到较低版本。
- **暂存后提交**：下载、解压和环境预检在暂存空间内进行，完成登记后才让托管使用该版本。预检失败的目标版本会留下备忘，避免重复下载。实际顺序见[项目更新](./update.md)。
- **可验证的下载**：区间差量重建发行包的内容。无法验证或继续下载整包更合适时退回全量。第三方镜像有整包摘要才参与下载。
- **回收与恢复**：回收以引用为依据，在启动时复核。切换视图时保留账号运行状态，版本相关缓存随新版本提供。切换记录供启动后完成中断的目录交接。

## 任务与设备

- **任务实例**：账号快照保留队列顺序、启用状态和任务实例选项。同一项目任务可有多份实例，周期任务的完成标记按任务名计算。失效的项目任务在队列中保留到用户删除，运行时跳过并记录。
- **运行信号**：账号整次时限和单任务时限由宿主和 worker 共同处理。实验性的原地打转检测依赖实际节点与动作信息。维护、客户端需更新等信号来自项目公开声明。
- **失败后的重试**：默认重跑非周期任务。已成功且明确可跳过重跑的任务由风味声明。每次尝试保留独立日志。
- **客户端生命周期**：`DirectExe` 和 `URL` 关闭由本次运行启动的客户端。`AttachOnly` 的兜底关闭只在最终收尾生效，并受 `Game.CloseMode` 和进程启动时间约束。完整规则见[运行](./run.md#pc-游戏启停)。

## 界面与风味

- **公共页面**：托管和账号页共享导入、队列与进度面板。风味先用差异配置和插入点，需要替换分节时沿用公共属性与事件契约。见[前端与交互](./frontend.md)。
- **运行语义**：风味钩子处理项目识别、特有任务或选项。通用引擎继续提供调度、通知、更新及任务收尾。具体扩展位置见[风味机制](./flavor.md)。
- **信息保护**：编辑界面、日志与问题包分别按其数据流处理密码字段。带密码输入的项目仅导出符合打码约束的运行日志。见[外壳配置导入与问题包](./shell-import-and-issue-report.md)。
