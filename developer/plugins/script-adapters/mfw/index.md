# MFW 设计总览

MFW 是 AUTO-MAS 运行 MaaFramework 项目的通用引擎，位于 `app/task/MaaFW/`。它从项目的 `interface.json` 读取任务、资源和控制器，在托管自己的项目视图中运行。M9A、MSS 通过风味配置与钩子补充项目独有能力。

## 阅读顺序

1. **开发风味**：从[风味专项开发](./develop.md)完成配置登记、后端钩子和前端描述对象。可选钩子及现有风味见[风味机制](./flavor.md)。
2. **理解导入和更新**：先看[总体架构](./architecture.md)的模块职责，再看[导入与载荷视图](./import-and-payload.md)、[项目更新](./update.md)如何维护项目版本。
3. **理解任务执行**：从[运行](./run.md)追踪任务快照到 worker 的过程，从[运行环境](./runtime-env.md)了解解释器、原生库和依赖安装。
4. **维护用户入口**：见[前端与交互](./frontend.md)、[外壳配置导入与问题包](./shell-import-and-issue-report.md)。
5. **查找设计依据**：并发、版本同步、任务重试与风味扩展的约束见[设计取舍](./tradeoffs.md)。

文中 `MaaFW/` 是主程序中的 `app/task/MaaFW/`。改动前阅读该目录的 `AGENTS.md`。改动 M9A、MSS 时，还需参考各自任务目录的说明。

## 术语

- **项目与导入**
  - **项目接口**：项目根的 `interface.json`，遵循 ProjectInterface（PI）协议。
  - **外壳**：项目的图形或命令行程序，例如 MFAAvalonia、MXU、MFW-PyQt6、MaaPiCli。MAS 通过 MFW 引擎运行项目。
  - **来源目录**：用户选择导入的目录，记录在 `Info.Path`。
  - **投影**：按项目接口和投影规则选取导入或更新所需文件。
- **载荷与视图**
  - **谱系**：项目身份，依序取 `mirrorchyan_rid`、`github`、`name`。
  - **组**：同一谱系、同一更新渠道的托管集合，组内同步到同一载荷。
  - **载荷**：按谱系、版本及内容哈希登记的不可变项目文件树。
  - **视图**：某托管使用的完整项目目录。可共享的内容通过硬链接复用；界面称为“副本”。
- **运行**
  - **风味**：`MaaFWConfig` 子类和项目钩子对象，通过通用引擎识别并运行特定项目。
  - **受管任务**：由风味决定是否、何时执行的任务，例如 M9A 的部分启动与退出任务。
  - **运行池**：runner 的基础虚拟环境，以及按版本存放的 Python binding 和原生库。
  - **binding**：供 Python 调用 MaaFramework 的 `maafw` 包，版本需与运行加载的原生库一致。
  - **worker**：运行器子进程，使用运行池并依赖引擎核心包。
  - **agent**：项目提供的自定义识别或动作进程。
  - **预检**：登记更新载荷前，在暂存目录准备一次运行环境。
