# 风味机制

风味由 `MaaFWConfig` 的子类和 `FLAVOR` 指向的钩子对象组成。后端引擎通过钩子识别项目、调整任务，前端通过注册表提供文案和组件。具体接入步骤见[风味专项开发](./develop.md)。

## 什么时候做风味

1. **识别项目**：通过项目接口的公开标识判断风味。导入后按 `CLASS_BOOK` 的登记顺序匹配，切换类型时保留托管 UID。
2. **声明项目差异**：通过钩子提供运行前编排、受管任务和项目专有设置。MFW 统一承担导入、更新、运行环境、任务执行、通知与计次。
3. **选择扩展位置**：通用能力在引擎内实现。外部脚本若需要原生配置会话或独立运行契约，按[专项适配入口](../index.md)选择接入方式。

## 后端协议与可选钩子

协议与全部契约写在 `MaaFW/tools/embedded/flavor.py` 的模块说明里，下表是摘要。M9A 的实现在 `app/task/M9A/flavor.py`，MSS 在 `app/task/MSS/flavor.py`。

| 成员                                                                                                                                 | 必需 | 何时调用 / 效果                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------ | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type_key: str`                                                                                                                      | 是   | 托管类型键，日志与通知里用                                                                                                                                                                                                                                                                                                                                     |
| `matches_project(interface_model) -> bool`                                                                                           | 是   | 导入后决定托管类型。`flavor.decide_project_config_class` 按 `CLASS_BOOK` 的登记顺序取第一个认领者，否则通用 `MaaFWConfig`；抛异常只告警                                                                                                                                                                                                                        |
| `decorate_selection(interface_model, task_ids, task_options, *, context)`                                                            | 是   | 队列归一化（并剔掉不可选任务、今天不在运行日的实例）之后、建运行计划之前调一次，返回新的 `(task_ids, task_options)`。在工作线程里运行。`context` 是只读的 `MaaFWSelectionContext`，字段见下面“选择上下文”                                                                                                                                                      |
| `sanitize_task_snapshot(interface_model, snapshot, *, script_config, resource_name, user_info)`                                      | 否   | 账号页保存、外壳配置导入建账号、配置恢复写 `Task.TaskSnapshot` 之前调用；返回整理后的快照与要一并写进 `Info` 的字段。读不到 interface 时不调用                                                                                                                                                                                                                 |
| `async ensure_game_updated(*, script_config, resource_name, package_name, adb_path, adb_address, if_auto_install, progress)`         | 否   | `Run.GameUpdateMode` 不是关闭、控制器是 ADB 时，在启动模拟器之后、第一个任务之前每个账号每次运行调一次。返回 `app.utils.common.game_update.GameUpdateResult`：需要手动更新时本账号判失败且**不重试**；抛异常只告警，`CancelledError` 必须向上传                                                                                                                |
| `async ensure_logged_in(*, script_config, user_config, resource_name, package_name, adb_path, adb_address, progress, host_adb=None)` | 否   | ADB 控制器、MAS 启动模拟器之后、第一个任务之前，紧跟 `ensure_game_updated`。返回 `str`（写进运行日志，空串表示没做事）或 `StartupTask(deadline, entry)`；登录成功才记完成，失败时下次尝试、重试重启客户端后都会重新调。无法继续时抛 `MaaFWLoginRequired`，文案直接给用户看，按普通失败走重试；`CancelledError` 必须向上传。Win32 控制器以空 `adb_address` 调用 |
| `abort_round_entries: dict[str, str]`                                                                                                | 否   | 关键任务（entry → 失败时的说明）：失败或单任务超时即结束本轮，照常重试                                                                                                                                                                                                                                                                                         |
| `nonfatal_entries: dict[str, str]`                                                                                                   | 否   | 收尾任务：失败、超时、原地打转、被脚本侧强停都只截图记一行，不计入本轮失败、不触发重试；优先于「第一个任务超时就结束本轮」；与关键任务重复声明时按收尾处理。用户停止、整轮时限、信号、游戏没能启动先于它处理（[#1296][1296]）                                                                                                                                  |
| `skip_on_retry_entries: frozenset[str]`                                                                                              | 否   | 重试时，本次运行里任一次尝试已完成过的这些任务不再补跑（按任务名判断；同名任务在计划里有多份时全部重跑）；worker 崩溃、拿不到结果的那次尝试不参与（[#1296][1296]）                                                                                                                                                                                             |
| `unselectable_entries: dict[str, str]`                                                                                               | 否   | 不可选任务（entry → 原因）：预览返回 `unselectableReason`；账号页不让选，已在队列里的照常显示可删；运行时在 `decorate_selection` 之前剔掉并记一行。因此优先于上面三种声明（[#1296][1296]）                                                                                                                                                                     |
| `no_default_fallback_inputs: frozenset[tuple[str, str]]`                                                                             | 否   | `(选项名, 字段名)`：字符串输入没填时，引擎默认回落 interface 的 `default`，列在这里的字段不回落、没填就下发空串。两条建计划的路都传；`/maafw/preview` 把这些字段的 `default` 置空，账号页不会把它显示成没填时的值。只列 `default` 是字面量占位、真下发会出错的字段                                                                                             |
| `retype_notice_lines(*, entering, has_users) -> list[str]`                                                                           | 否   | 项目导入后脚本按项目换类型时，换入的风味以 `entering=True`、换出的以 `entering=False` 各调一次；返回的行接在系统通知“已按项目识别为 …”下面。`has_users` 为假时，只对已有账号说的话不要返回。抛异常只告警                                                                                                                                                       |
| 配置类属性 `DEFAULT_TASK_TIME_LIMIT_OVERRIDES`                                                                                       | 否   | 风味内置的按任务时限（JSON 字符串，任务名 → 分钟）；通用 MFW 托管因导入项目换成该风味时，托管的 `Run.TaskTimeLimitOverrides` 还是空的才补上（`flavor.user_config_type_transform`）                                                                                                                                                                             |

### 选择上下文与辅助函数

`decorate_selection` 的 `context` 与两个小工具都在 `app/task/MaaFW/tools/embedded/flavor_support.py`。这个模块只依赖标准库与 interface 模型：特调包在启动早期就会被配置迁移导入，导入期不能拉起建计划的核心 runner。`flavor.py` 把它们原样转出。

| 名字                                          | 内容                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `MaaFWSelectionContext.script_config`         | 脚本（托管）配置                                                                                  |
| `MaaFWSelectionContext.user_config`           | 本次运行的账号配置                                                                                |
| `MaaFWSelectionContext.resource_name`         | 运行时实际生效的资源（`resolve_run_selection`，脚本资源留空时已按控制器回落），特调不要自己再回落 |
| `MaaFWSelectionContext.excluded_task_ids`     | 引擎判定本轮不跑的实例 ID（`frozenset`）：红灯的、今天不在运行日的                                |
| `MaaFWSelectionContext.log`                   | 写一行账号运行日志，钩子在工作线程里可以直接调                                                    |
| `task_name_for_entry(interface_model, entry)` | interface 里第一个 `entry` 等于给定值的任务名，找不到返回 `None`                                  |
| `config_value(config, group, name)`           | `config.<group>.<name>`，缺分组或缺字段返回 `None`                                                |

钩子自己读账号配置补任务时，不要补回 `excluded_task_ids` 里的实例，也不要自己再解析快照去判红灯或星期。核心建计划时还会按红灯再滤一遍装饰结果，补回的红灯实例照样不跑；今天不在运行日的实例由引擎在交给钩子之前拿走，钩子的输出里没有它们时，引擎会把它们接在装饰结果后面交给核心，由核心在建计划前排除、记成跳过。

### 可选成员的加载

`MaaFWFlavor` 是 `runtime_checkable` 的 Protocol。把可选钩子写进协议，没实现它的风味在 `isinstance` 检查时就不满足协议，整个退回通用 MFW。所以可选成员一律用 `getattr` 探测（`resolve_game_update_hook`、`resolve_snapshot_sanitizer`、`unselectable_entries` 等），缺了就当没有。`skip_on_retry_entries` 用集合而另几个用字典，是因为它没有逐任务的话要说——跳过原因统一是「前面的尝试已完成」。

### 注册与运行约束

| 约束                                                                                                                                                                                                                                                                                                          | 为什么                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 配置类在 `app/models/config/script.py`，`XConfig(MaaFWConfig)` 与 `MaaFWConfig` 同形：类属性 `DEFAULT_SCRIPT_NAME`、`USER_CONFIG_CLASS`、`FLAVOR` 必写，另按需重写 `Info.Name`、`Run.TaskTimeLimitOverrides`、`Game.WaitTime` 等分组默认值（`M9AConfig` 是参考）；`FLAVOR` 是字符串，由引擎按需导入           | `app.models` 不能反向导入 `app.task`；`ConfigBase` 子类不能在 `super().__init__()` 之后覆盖条目，所以用类属性 |
| 类型登记在 `app/models/config/__init__.py` 的 `CLASS_BOOK`（计划表类在 `plan.py`，`PLAN_BOOK` 也在这个 `__init__.py`）；`TYPE_BOOK` 在 `app/utils/common/constants.py`                                                                                                                                        | `CLASS_BOOK` 的登记顺序决定多个风味同时认领时谁赢；托管下拉框按 `TYPE_BOOK` 取类型名，漏登记会抛 `KeyError`   |
| 运行入口在 `app/task/MaaFW/registration.py`：风味要写进家族声明 `ScriptRegistration` 的 `run_types`；`app/core/config/manager.py`里 `isinstance(…, MaaFWConfig)` 的分支天然覆盖子类，不要再加风味分支                                                                                                         | 宿主生成的运行索引按类型精确匹配，子类要单独登记                                                              |
| 接口类型在 `app/api/scripts/management.py` 与 `app/api/scripts/users.py`：配置载荷与输入别名、`ScriptIndexItem.type` / `UserIndexItem.type` 与 `ScriptCreateIn.type` 的枚举、三处联合类型（脚本侧 `ScriptCreateOut`、`ScriptGetOut`、`ScriptUpdateIn`，账号侧 `UserGetOut`、`UserCreateOut`、`UserUpdateIn`） | M9A、MSS 在这些位置都出现；`app/models/schema.py` 不放这些类型                                                |
| 凡是按类装账号子配置的地方都用 `type(script_config).USER_CONFIG_CLASS`                                                                                                                                                                                                                                        | 写死 `MaaFWUserConfig` 会让子类账号全部丢失，只报「MFW 没有可运行的账号」（`embedded_manager.py` 的检查文案） |
| `decorate_selection` 在工作线程里：用 `context.log` 写日志，由引擎转回事件循环；检查阶段的提示会在本账号日志建好后并入（[#1197][1197]）                                                                                                                                                                       | 直接写界面日志会抛「no running event loop」                                                                   |
| 风味在 `decorate_selection` 里抛异常 = 运行计划构建失败：该账号记“异常”、发错误通知、不运行、不重试，异常原文接在“无法构建 MaaFW 运行计划”后面给用户看，其他账号照常                                                                                                                                          | M9A 用它拒绝需要拆分的账号                                                                                    |
| 返回新的列表与字典，不改写入参；按 entry 找不到任务时写一行账号日志后跳过                                                                                                                                                                                                                                     | 任务名可能随项目版本变                                                                                        |

### 路由与页面宿主

- 路由由 `frontend/src/router/maafwFlavorRoutes.ts` 按注册表生成，每个类型四条：托管编辑、项目引导、添加账号、编辑账号。新增风味不用改路由。
- 页面宿主 `MaaFWFlavor/MaaFWPageHost.vue`（逻辑在 `useMaaFWPageHost.ts`）读到托管详情后按**实际类型**选页面：地址后缀与类型不符时 `replace` 到正确那条；导入后同一会话里类型变了，不跳转、就地换页面，引导进度不丢（[#1163][1163]）。
- 代价：页面要等读到托管详情（几毫秒）才渲染；换来第一帧就是正确风味的图标与标题。

### 声明页面差异

描述对象只承载身份、文案、受管任务这类数据与独有组件，不承载「这个风味要不要做某种通用行为」的布尔量。行为差异要么是数据（受管任务列表、插入点组件），要么由托管实际类型推出。加一个布尔开关，等于把 `type === 'X'` 换个写法塞回公共代码，几个开关一组合，公共页面又变回按类型分支。目前没有自动检查拦这件事，靠评审把关（见文末检查清单）。

## MSS（星塔旅人 / MaaStellaSora）

后端 `app/task/MSS/flavor.py`，前端 `MaaFWFlavor/mss/`。

| 项           | 设计                                                                                                                                                                                                                                                                                                                                                                                                  | 为什么                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 认领         | `mirrorchyan_rid == SSAH`，或 `github` 仓库名 / `name` 等于 `MaaStellaSora` 或以 `MaaStellaSora-` 开头；只给组织主页时取不到仓库名，不认领（[#1141][1141]）                                                                                                                                                                                                                                           | 官方版与个人版等衍生版都认；同前缀但没有连字符的不认                       |
| 认领只定类型 | 更新谱系仍按 interface 里的原文 `mirrorchyan_rid` / `github` / `name` 各自分开                                                                                                                                                                                                                                                                                                                        | 衍生版不会被官方更新覆盖——除非它照抄了官方的 `mirrorchyan_rid`             |
| 计划表       | 账号 `Info.PlanMode` 引用了 MSS 计划表时，按当天的槽位改写 entry `战斗_入口`（悬赏试炼快速战斗）的五个选项；队列里没有这个任务就补上；关卡名不在 interface 的 case 里就整条跳过；选「固定」时不动（[#959][959]）                                                                                                                                                                                      | 保留原专项的计划表能力                                                     |
| 活动         | 队列里有 `活动快速战斗_入口` 时查一次官网排期（`app/tools/common/game_calendar/stella.py`）：有活动就挪到悬赏试炼前，确实没有就摘掉，取不到数据就原样跑；队列里只剩活动任务时不摘空。`Info.IfActivityFirst`（默认开）开着且确认在活动期时，队列里没加也会自动补上                                                                                                                                     | 摘空会让引擎判「无法构建运行计划」；取不到数据时乱加会多跑一个不该跑的任务 |

| 重试不补跑   | 声明了 `skip_on_retry_entries`：已确认的日常与挑战任务（活动快速战斗、悬赏试炼、新版爬塔、灾变防线等 15 个 entry）本次运行里成功过，重试不再补跑；失败、超时、没轮到的照跑。登录不列，重试重启游戏后仍要登录                                                                                                                                                                                          | 重跑已领完、已打完的只是白等；上游新增任务默认保留重跑                     |
| 只适配桌面端 | 托管页控制方式一步顶部写明原因；引擎不拦 ADB                                                                                                                                                                                                                                                                                                                                                          | 模拟器端启动不了游戏                                                       |
| 配置         | `MSSConfig` 与 `MaaFWConfig` 同形（只重写了 `Info.Name` 默认值）；`MSSUserConfig` 提供计划表与活动优先字段 `Info.PlanMode`（`ref("PlanConfig", …)`，默认 `Fixed`）、`Info.IfActivityFirst`。计划表类 `MSSPlanConfig` 在 `app/models/config/plan.py`，登记在 `PLAN_BOOK`，消费方是 `PLAN_CONSUMER_VALUES` 里的 `mss`。需要计划表的新风味要多做的步骤见操作指南 [需要计划表时](./develop.md#plan-table) | —                                                                          |
