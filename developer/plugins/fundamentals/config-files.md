# 配置文件与数据

插件配置位于后端工作目录。源码启动时从主仓根目录定位，其他启动方式以后端启动日志中的工作目录为准。

## 文件位置

- **宿主管理的数据**

  - `config/plugin_registry.yaml`：插件注册表，保存身份、版本、来源、启用意图和运行状态。通过插件中心变更启用状态。
  - `config/plugin_catalog.yaml`：插件市场目录。刷新市场时更新。
  - `data/plugin-market-cache.json`：数据站目录响应缓存及其 ETag。

- **插件自有配置**

  - `config/plugins/<插件 ID>.yaml`：仅声明 `config_class` 的插件拥有自有配置文件。实例通过 `self.config` 使用，字段和界面声明见[配置声明](./schema.md)。
  - 配置节点的 `uid` 用于定位这份配置，插件注册项的 `uid` 用于定位注册表条目。

- **安装环境**

  - `plugins/pypi/site-packages/`：宿主维护的已安装插件与共享依赖。版本和环境切换由[宿主与运行机制](./runtime.md)描述。

## 启用时加载配置

1. **构造**：宿主按 `config_class` 和插件 ID 创建文件关联的配置实例。
2. **激活**：启用阶段读回已有文件，按配置框架校验和激活。`on_enable()` 读取已激活的 `self.config`。
3. **提交**：插件在配置分组赋值，再调用 `commit()`。宿主通过配置框架负责持久化。启用期间，插件中心也可以通过通用设置页读写该配置。
4. **释放**：停用时保存并释放运行配置，文件留给下次启用。自有配置中的嵌套集合由所属 Entry 管理，集合声明省略根集合专用的 `name=`。

## 停用、重载和卸载的影响

- **停用**

  - 注册表保留，启用意图写为关闭，自有 YAML 文件保留。
  - 如果插件登记了专项或游戏类型，宿主会在停用时移除这些类型以及对应的托管、账号、计划表或游戏、设备配置。插件中心通过 `disableImpact` 显示影响范围。普通功能插件的停用影响其自身能力。

- **重载**

  - 宿主重新导入代码并恢复原先启用的插件。适配器重载保留配置身份和数据。

- **卸载**

  - 发行包卸载完成后移除其注册项和自有配置。源码插件和内置核心插件通过各自的来源管理。
  - 本地源码目录被移除时，注册表可以标为 `package_removed`，已有自有配置仍保留。
