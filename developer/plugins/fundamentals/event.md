# 事件系统

插件以宿主生命周期、配置变更和界面请求为入口。需要在插件之间调用能力时使用[服务系统](./service.md)。需要更新前端时使用宿主已有的推送与查询流程。

## 选择接入入口

- **插件启停或重载**

  - 使用 `BasePlugin` 的[生命周期钩子](./index.md#生命周期钩子)。把预检和运行资源的创建、释放放在各自阶段。

- **配置发生变化**

  - 使用配置节点的信号。回调在触发变更的事务中执行。见[配置信号与事件](../../core/config.md#配置信号与事件)。

- **用户发起操作**

  - 在配置类声明[触发器](./schema.md#触发器)。处理器由宿主管理，运行结果通过任务 UUID 查询。

- **脚本执行到达某个阶段**

  - 专项插件在[调度链的 L3 或 L4](../../core/scheduling.md#任务执行流程)实现自己的阶段逻辑。主程序向前端发送的任务事件属于调度界面的传输契约。

## 配置信号

配置类和配置实例都可以订阅。通常在 `on_enable()` 订阅，在 `on_disable()` 退订。退出或启用失败后，按实际取得的资源执行相应清理。

```python
async def <字段变更回调>(sender, event):
    <处理逻辑>

<配置类或实例>.connect(
    receiver=<字段变更回调>,
    phase=<事件阶段>,
    kind=<事件类型>,
    group=<分组名>,
    field=<字段名>,
)
<配置类或实例>.disconnect(
    receiver=<字段变更回调>,
    phase=<事件阶段>,
    kind=<事件类型>,
    group=<分组名>,
    field=<字段名>,
)
```

- **订阅参数**

  - `receiver=`：同步或异步函数，接收 `sender` 和 `event`。退订使用同一个函数对象、订阅目标及过滤条件。
  - `phase=`：默认 `"runtime"`，也可选 `"init"` 或 `"both"`。运行期的 `set` 只在值变化时触发，初始化赋值使用 `init_set`。
  - `kind=`、`group=`、`field=`：按事件种类、分组和字段过滤。集合事件省略分组和字段。

- **事务中的回调**

  - 回调需要修改配置时，在返回前提交自己产生的暂存。
  - 普通字段和集合事件保留配置框架的事务语义。前端刷新使用根事务提交后的配置变更通知。

## WebSocket 推送

使用 `auto_mas_core.Publisher` 向宿主前端的主连接发送消息。消费端在主程序前端实现，并按同一 `id` 和 `type` 订阅。

```python
from auto_mas_core import Publisher

<是否已发送> = await Publisher.send(
    id=<路由标识>,
    type=<消息类型>,
    data=<消息数据>,
)
```

- **推送参数**

  - `id=`：前端用于匹配订阅的路由标识。
  - `type=`：与消费端约定的消息类型。宿主已有类型遵循其约定的数据结构。
  - `data=`：Pydantic 模型或可序列化为 JSON 的映射。
  - `<是否已发送>`：主连接不可用时返回 `False`。需要恢复页面状态时，在重连后通过查询取得快照。

配置触发器和控制器状态变化使用 `config.ui.changed` 通知受影响配置节点。接入步骤见[配置界面的实时同步](./frontend.md#配置界面的实时同步)。
