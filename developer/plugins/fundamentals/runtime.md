# 插件宿主与运行机制

插件包声明它提供的能力，宿主负责发现、加载、启停和安装交接。加载、市场与源码监听位于 `app/plugin/runtime/`，实际运行编排位于 `app/core/plugin/`。首次接入从[最小插件](./index.md#最小插件)开始。

## 从项目到运行实例

- **项目身份**

  - 插件 ID 标识注册项、语言资源前缀和同 ID 候选，例如 `mumu_adapter`。
  - 发行名用于安装、依赖和版本求解，例如 `auto-mas-mumu-adapter`。
  - 导入名是宿主从候选目录加载的 Python 包名。游戏或托管类型键标识相应配置类型，单独声明。

- **文件位置**

  - 源码项目在后端工作目录的 `plugins/<插件 ID>/`。运行期已安装包位于 `plugins/pypi/site-packages/`。
  - Runtime 从当前后端源码树加载 SDK。用户插件与依赖保存在安装根目录，切换后端版本时继续保留。

1. **发现候选**：扫描含 `pyproject.toml` 和 `src/` 的本地项目，再从已安装发行包的元数据识别插件。
2. **选择来源**：同 ID 的源码和发行包同时存在时选源码。验证 wheel 时，移出同 ID 源码并重启，确认宿主确实加载已安装包。
3. **加载声明**：导入候选的包，读取 `PLUGIN` 和服务依赖声明。发行版本、SDK 依赖范围和 `PLUGIN_API_VERSION` 各自独立。

## 启用、停用和重载

`app/core/plugin/manager.py` 负责协调生命周期。业务资源由插件的[生命周期钩子](./index.md#生命周期钩子)管理。

1. **启用**：创建实例并绑定任务组、服务，运行 `pre_enable()`。随后启用必需服务的提供方、登记适配类型并激活配置，再执行 `on_enable()`，成功后发布服务和 HTTP 路由。
2. **停用**：执行预检，按依赖关系处理下游，关闭新受管调用，等待在途工作并回收后台任务。执行 `on_disable()` 后，宿主释放配置并撤销注册能力。
3. **重载**：在旧实例执行重载钩子，卸下旧运行能力并导入新类，然后启用新实例和原先受影响的依赖方。适配器重载保留配置标识。常规停用和卸载的配置影响见[配置文件与数据](./config-files.md)。
4. **失败或退出**：运行期故障由 `on_fail_cleanup()` 回收业务资源，宿主负责回退注册。进程退出由 `on_teardown()` 收尾。

HTTP、服务及受管适配器调用经过调用门。释放实例时停止接收新调用，并等待其他在途调用退出。同步网关处理器由异步网关直接调用，包含耗时阻塞操作时由插件将该操作移出事件循环。

## 市场、安装和更新

市场目录和本机注册表各自维护。刷新目录时依次尝试数据站、PyPI 和配置的镜像，取得完整结果才替换目录。所有来源失败时保留已有目录。

1. **求解候选环境**：宿主用当前应用锁定的依赖与已安装插件共同求解，已安装但禁用的插件仍参与约束。
2. **准备切换**：共享依赖已在运行时加载且需要更换时，安装进入等待重启状态。候选环境准备完成后通过[插件中心的操作](./frontend.md#插件中心的操作)交接。
3. **确认结果**：新进程成功加载才确认切换。失败时可以恢复旧环境。应用更新预检使用目标版本的 Python 和依赖文件计算兼容组合，实际启动还要完成插件与业务配置加载。

Runtime 自身更新另有生命周期。Runtime 托管后端时，核心健康和业务就绪分别报告。业务调用应在 `businessStatus` 就绪后开始。

## 背景任务、下载与预下载

插件自有工作通过[后台任务组](./index.md#self-background-tasks)提交。配置按钮调用独立的[触发器](./schema.md#触发器)，由配置管理器跟踪运行状态与结果。

```python
from auto_mas_core import DownloadRequest
from auto_mas_core.services import Downloads

<下载请求> = DownloadRequest(url=<资源地址>, key=<稳定资源键>)
if Downloads.request(<下载请求>, owner=<使用者标识>):
    try:
        <下载快照> = await Downloads.wait(<下载请求>)
        if <下载快照>.state == "succeeded":
            <使用下载文件>
    finally:
        await Downloads.release(<下载请求>.cache_key, owner=<使用者标识>)
```

- **资源身份**

  - `url=`：实际下载地址。默认也是资源键。
  - `key=`：可选的稳定资源键。对会更新签名的地址，使用插件命名空间中的稳定键。
  - `rid`、`content_hash`：内容身份优先使用 `rid`，其次使用内容哈希。复用相同资源键更新文件时提供能区分内容的身份。

- **申请和释放**

  - `request()` 受理后才调用 `wait()`。成功快照的 `path` 指向可用文件。
  - 使用完毕后按相同资源键和 `owner` 释放引用。最后一个引用释放后，未完成的下载会被取消。

专项可为 `ScriptTypeDecl` 提供异步 `prefetch_check`，返回所需的 `DownloadRequest` 列表。宿主负责提前申请和收尾释放，实际派发前在持锁的托管配置上重新核对需求。L3 从任务上下文的 `prefetch_paths` 读取已交付路径，需要时显式交给账号执行器。
