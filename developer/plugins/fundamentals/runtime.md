# 插件生命周期

宿主在 `app/core/plugin/manager.py` 中编排插件的加载、启用、停用、重载、卸载和退出。插件类按需覆盖 `BasePlugin` 定义的异步钩子，宿主在相应阶段调用插件实例上的实现。

本章节以市场插件为例。本地源码插件无法通过插件中心卸载。通过市场安装或更新同 ID 的发行包前，须先将本地插件项目移出宿主扫描范围。

- **生命周期钩子**：`BasePlugin` 提供的是空生命周期钩子，插件直接覆写对应方法即可，无需调用父类方法。

- **服务的上下游**：以当前插件为参照，为其提供 `requires` 中所列服务的插件是上游提供方。通过 `requires` 依赖当前插件所提供服务的插件是下游依赖方。

## 加载

宿主通过 `app/plugin/runtime/loader.py` 导入插件包并取得插件类，供启用阶段创建插件实例。

1. **导入插件包**：宿主根据插件注册项中的导入包名和来源定位顶层 Python 包，并执行包入口的 `__init__.py`。插件需要在该文件中将插件类导出为 `PLUGIN`。
2. **校验插件**：宿主确认 `PLUGIN` 是 `BasePlugin` 的子类。插件导出 `PLUGIN_API_VERSION` 时，宿主还会确认协议主版本一致。

- **加载结果**
  - `disabled`：加载成功，可启用、重载、卸载。宿主持有插件类，并记录 `requires` 和 `wants` 声明的服务名。
  - `fault_load`：导入或校验失败，可卸载。宿主记录错误，供插件中心展示。

## 启用

宿主用已加载的插件类创建实例，并登记插件可供调用的能力。

1. **创建实例**：宿主检查上游服务提供方是否已加载。插件类声明了 `config_class` 时，宿主先构建冷态插件配置。创建实例时，宿主传入插件注册项和插件配置，插件未声明配置类时配置参数为 `None`。宿主随后绑定服务查询入口和后台任务组。
2. **启用准备**：宿主调用插件实例的 `pre_enable()`，插件可以在这里检查外部程序、运行环境等启用条件。需要依赖服务或插件配置已就绪的工作须放在 `on_enable()`。
3. **上游插件级联启用**：宿主按 `requires` 声明的服务名递归启用上游提供方，复用已启用的上游插件。当前插件声明了配置类时，宿主随后激活插件配置。
4. **启用插件**：宿主调用插件实例的 `on_enable()`，插件可以在这里读取插件配置、调用上游提供的必需服务、创建客户端或订阅配置信号。
5. **登记能力**：宿主登记插件提供的服务、HTTP 路由和适配类型。

- **启用结果**
  - `enabled`：启用成功，可停用、重载、卸载。宿主保留插件实例，插件登记的能力可供调用。
  - `fault_runtime`：`pre_enable()` 通过后启用失败，可重试启用、重载、卸载。宿主撤销本次已登记的能力，清理插件实例并记录错误。
  - **启用准备失败**：宿主在检查依赖、创建实例或调用 `pre_enable()` 时遇到错误，报告启用失败并保留原有插件状态。修正错误后可再次尝试启用。

## 停用

宿主撤销插件提供的能力并释放插件实例，保留已加载的插件类供再次启用。

1. **停用准备**：宿主暂停当前插件及其下游依赖方的调用入口，等待在途操作结束，并检查要释放的适配配置是否被占用。宿主随后调用插件实例的 `pre_disable()`，插件可以在这里检查配置会话等业务操作是否已结束。
2. **下游插件级联停用**：宿主按必需服务的依赖关系，递归停用已启用的下游依赖方。
3. **停用插件**：宿主回收当前插件实例的后台任务，再调用 `on_disable()`，插件可以在这里关闭启用时创建的客户端、外部进程或订阅。
4. **注销能力**：宿主保存并释放插件配置，撤销服务、HTTP 路由及适配类型的登记，最后释放插件实例。

- **停用结果**
  - `disabled`：停用成功，可重新启用、重载、卸载。
  - `fault_runtime`：停用过程中发生故障，可重试启用、重载、卸载。宿主进入失败清理流程并记录错误。
  - **停用准备失败**：检查适配配置或调用 `pre_disable()` 时出错，宿主保留原有插件状态。修正错误后可再次尝试停用。

## 重载

宿主重新导入当前插件的插件类。已启用的下游依赖方随本次重载停用，宿主随后按依赖顺序重新启用它们。

1. **重载准备**：宿主暂停当前插件及其下游依赖方的调用，等待在途操作结束，并检查适配配置是否被占用。宿主在已有的插件实例上调用 `pre_reload()`，插件可以在这里检查当前业务是否允许重载。
2. **下游插件级联停用**：宿主递归停用已启用的下游依赖方，并记下本次停用的插件及其依赖关系。
3. **重载插件**：已有插件实例时，宿主在原实例上调用 `on_reload()`，插件可以在这里保存跨重载所需的业务状态。若插件在重载前已启用，宿主先停用该插件。宿主重新导入插件包、校验插件入口，并将重新加载的插件类写入插件注册项，随后重新启用原本已启用的插件。
4. **下游插件级联恢复**：宿主从上游到下游依次恢复本次停用的下游插件。某个下游插件恢复失败时，宿主将该插件标记为 `fault_runtime` 并继续恢复其他分支。

- **重载结果**
  - `enabled`：重载成功，插件恢复启用，可停用、重载、卸载。
  - `disabled`：重载成功，插件处于停用状态，可启用、重载、卸载。
  - `fault_runtime`：重载过程中发生故障，可重试启用、重载、卸载。宿主进入失败清理流程并记录错误。
  - **重载准备失败**：检查适配配置或调用 `pre_reload()` 时出错，宿主保留原有插件状态。修正错误后可再次尝试重载。

## 卸载

宿主释放插件运行时资源，并移除插件发行包、插件配置文件和插件注册项。插件中心会提示本次卸载可能影响的适配配置。

1. **卸载准备**：宿主暂停当前插件及其下游依赖方的调用，等待在途操作结束，再调用已有插件实例的 `pre_unload()`，插件可以在这里确认自己管理的文件是否允许清理。
2. **下游插件级联卸载**：宿主按必需服务的依赖关系递归卸载下游插件，该卸载操作仅释放其运行时资源并移除插件注册项，不会移除发行包和插件配置文件。
3. **卸载插件**：宿主在卸载开始时保留已有实例的引用。若插件原本已启用，宿主先执行停用流程。若之前保留了实例，宿主随后在该实例上调用 `on_unload()`，插件可以在这里清理卸载时才需要移除的资源，例如自行建立的缓存。宿主最后释放插件类，移除当前插件的发行包和插件配置文件，再移除插件注册项。

- **卸载结果**
  - **卸载成功**：可从插件市场重新安装。
  - `fault_load`：卸除运行时或删除发行包、插件配置文件时发生故障。宿主在保留的插件注册项中记录错误，可重试卸载。
  - **卸载准备失败**：宿主在调用 `pre_unload()` 时遇到错误，报告失败并保留原有插件状态。修正错误后可再次尝试卸载。

## 失败

生命周期操作进入故障处理流程时，宿主撤销相关登记并清理插件资源。

1. **回退宿主登记**：宿主撤销服务和 HTTP 路由的登记，释放插件配置并回收插件实例的后台任务。
2. **清理业务资源**：宿主需要通过原实例清理时，先回退专项适配的登记，再调用 `on_fail_cleanup(during, lifecycle_context, exc)`。插件可以在这里释放失败前已取得的资源。
   - `during`：实际出错的生命周期阶段。
   - `lifecycle_context`：本次操作的生命周期上下文。
   - `exc`：触发失败清理的异常。
3. **释放实例并记录错误**：宿主移除插件实例，并在插件注册项中记录引起这次故障的错误。

- **清理结果**：宿主根据原操作记录对应的故障状态。后续操作见各阶段的结果。

## 退出

宿主退出时，按依赖关系为已启用的插件收尾，并保存配置供下次启动读取。

1. **停止接收调用**：宿主关闭插件的服务和 HTTP 调用入口，等待在途调用结束。
2. **下游优先收尾**：宿主先处理下游依赖方，再处理上游服务提供方。宿主为已启用的插件实例回收后台任务，然后调用 `on_teardown()`。插件可以在这里关闭外部进程、连接和订阅。
3. **保存配置**：宿主在后端退出流程中统一保存配置，并保留插件注册项中的启用意图。

- **退出结果**
  - **收尾完成**：宿主下次启动时重新加载插件，并按保存的启用意图恢复插件。
  - **收尾失败**：某个插件的 `on_teardown()` 出错时，宿主记录错误并继续处理其他插件。
