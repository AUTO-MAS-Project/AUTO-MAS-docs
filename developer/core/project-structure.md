# 项目结构

AUTO-MAS 主仓库包含 Python 后端、Vue 渲染端和 Electron 桌面外壳。后端从根目录的 `main.py` 启动，应用源码放在 `app/`。前端项目放在 `frontend/`，页面与桌面进程分别位于 `frontend/src/` 和 `frontend/electron/`。下文路径均相对主仓库根目录。

## 后端

### 源码目录

| 路径            | 职责                                                                                                                  |
| --------------- | --------------------------------------------------------------------------------------------------------------------- |
| `main.py`       | 后端进程入口，初始化并启动 FastAPI 应用。                                                                             |
| `app/api/`      | HTTP 和 WebSocket 接口层。校验请求、调用业务入口、组装响应和接口错误。端点专用的请求和响应模型放在对应 API 文件。     |
| `app/core/`     | 主程序核心组件。负责配置、任务调度、游戏实例、通知、WebSocket、插件管理等应用级编排。                                 |
| `app/models/`   | 共享数据结构、类型契约和字段约束。跨模块的 HTTP 和 WebSocket 契约放在 `schema.py`，业务配置声明放在 `config/` 下。    |
| `app/config/`   | 通用配置框架，提供节点、字段、事务、锁、序列化和信号。`wire.py` 从配置声明派生接口所需的类型。                        |
| `app/services/` | 按功能组织跨平台服务。服务可以调用其他组件的公开入口，完整的服务实现留在所属模块。                                    |
| `app/utils/`    | 跨平台通用工具，接收参数并返回结果。项目内导入限于 `utils` 自身。                                                     |
| `app/tools/`    | 社区签到等独立工具功能。每项功能有自己的目录，集中放置专用模型、契约和各平台实现。项目内只依赖本功能和 `app/utils/`。 |
| `app/task/`     | 主程序现有的任务执行逻辑，包括托管、账号执行和仍在主程序内维护的专项适配。                                            |
| `app/plugin/`   | 插件基础契约和运行机制。插件在主程序中的接入和编排位于 `app/core/plugin/`，对外 SDK 位于 `plugins/auto_mas_core/`。   |
| `app/mystery/`  | 高级功能预留目录。                                                                                                    |

### 代码放置原则

- **按职责分层。** 路由处理输入输出，应用级编排交给 `core` 或对应服务。共享模型保存结构和约束，任务执行交给 `task` 及对应适配。功能优先放在所属层的单文件中，确需拆分时在该层建立功能包。只有大型核心组件需要把可独立复用的基础机制与主程序编排分开时，才在 `app/` 下另建基础包。
- **从组件公开入口调用。** 核心组件由所属模块持有单例，可从 `app.core` 按需取得，例如 `Config`、`Notify`。简单组件可在一个文件中定义实现和单例，复杂组件在自己的包内按职责分文件。每次任务独立创建的对象由对应任务管理。
- **配置分成框架、声明和应用管理。** 通用机制归 `app/config/`，业务字段归 `app/models/config/`，启动加载、业务读写、升级和备份归 `app/core/config/`。应用代码通过 `Config` 的路径属性定位资源与用户文件，独立工具所需的路径由调用方传入。
- **跨平台实现留在功能内部。** `services`、`utils` 和 `tools` 各自提供统一的公开入口。独立工具由调用方提供配置和上下文，调用方也负责配置回写、调度或通知。

## 前端

### Vue 渲染端

渲染端以 `frontend/src/main.ts` 为入口，通过 `App.vue` 装载应用。页面使用 Vue 3、TypeScript 和 Ant Design Vue，由 Vue Router 管理导航。

| 路径                                                                 | 职责                                                                                                                                                   |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `frontend/src/router/`                                               | 声明页面路由、导航和专项编辑器入口。                                                                                                                   |
| `frontend/src/views/`                                                | 路由页面及其业务流程。模块页面通常使用 `views/<模块>/index.vue`，也可以是单个页面文件。模块专用组件和逻辑随页面放置，例如 `views/<模块>/components/`。 |
| `frontend/src/components/`                                           | 多个页面共用的组件。                                                                                                                                   |
| `frontend/src/composables/`                                          | 跨页面复用的组合式函数。`useXxxApi.ts` 封装面向业务的请求，页面负责提交后的导航、弹窗和局部状态。                                                      |
| `frontend/src/api/`                                                  | 由后端 OpenAPI 生成的客户端、请求服务和接口类型。后端契约变化时通过生成命令更新。                                                                      |
| `frontend/src/services/`                                             | 渲染端基础服务，包括 Vue Query 配置、WebSocket 订阅和配置状态同步。                                                                                    |
| `frontend/src/stores/`                                               | Pinia 仓库，保存由客户端管理且需要在多个组件或页面间共享的响应式状态。                                                                                 |
| `frontend/src/types/`、`frontend/src/utils/`                         | 手写的领域类型及桌面桥接类型，以及可独立调用的工具函数。接口生成类型归 `src/api/`。                                                                    |
| `frontend/src/i18n/`、`frontend/src/styles/`、`frontend/src/assets/` | 分别存放国际化入口与相关逻辑、全局样式和渲染端资源。`src/style.css` 也是全局样式入口之一。                                                             |

组件和逻辑优先放在使用它的页面模块内，有跨模块复用时再提到共享目录。表单草稿和临时交互状态由使用它们的页面或组件管理，来自后端且需要共享的查询结果由 Vue Query 缓存。

### Electron 桌面端

| 路径                           | 职责                                                                                           |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| `frontend/electron/main.ts`    | 桌面主进程入口，组织窗口和应用生命周期。                                                       |
| `frontend/electron/preload.ts` | 向渲染端暴露 `window.electronAPI`，桥接桌面能力。类型位于 `frontend/src/types/electron.d.ts`。 |
| `frontend/electron/ipc/`       | 主进程 IPC 处理器，对接预加载脚本暴露的桌面入口。                                              |
| `frontend/electron/services/`  | 后端进程管理、Runtime、更新、文件等桌面能力的具体实现。                                        |

页面访问 Python 后端时，通过业务 composable 使用生成的客户端发送 HTTP 请求，并通过共享 WebSocket 服务接收推送。页面需要访问桌面能力时，调用 preload 暴露的接口，由 Electron 主进程处理。

## 工程目录

| 路径                                                                     | 内容                                                                   |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `res/`                                                                   | 主程序随附的资源和版本信息。                                           |
| `tests/`、`frontend/e2e/`                                                | Python 测试与 Playwright 测试。前端的 `*.test.ts` 与被测模块就近放置。 |
| `pyproject.toml`、`uv.lock`、`.python-version`                           | Python 项目和依赖声明、依赖锁文件、解释器版本。                        |
| `frontend/package.json`、`frontend/yarn.lock`、`frontend/vite.config.ts` | 前端依赖和命令、依赖锁文件、Vite 配置。                                |
