# 术语解释

在开始 AUTO-MAS 的开发之前，你需要了解本项目涉及到的专有术语，以免在沟通中出现理解偏差。

## 脚本相关术语

### 托管 | Script

AUTO-MAS 管理和调度外部脚本软件的基本单位。每个托管关联一个被管理软件，组织和管理其所有配置信息。

一个托管对应一个外部脚本软件，包含一或多个账号。

### 账号 | User

AUTO-MAS 是一款多脚本多配置管理工具，允许为每个脚本保存多套配置，「账号」本质上就是脚本的一份配置。因为每份配置通常对应一个用户或账号的信息，为便于沟通，才采用「账号」这一命名。

一个账号对应一个脚本配置，无下级单位。

### 计划表 | Plan

计划表是一份按周期轮换、可供账号绑定的表单。在实际使用中，部分账号的配置可能需要随星期轮换，多个账号可能需要同步调整一项配置。为减少这些高频修改场景的操作量，我们允许每个账号关联一个计划表。

一个账号可以关联一张计划表，一张计划表可以同时被多个账号关联。

## 配置相关术语

一个账号对象对应一个脚本配置，AUTO-MAS 采用直接存储脚本所有配置文件的方式保存脚本配置。这使得 AUTO-MAS 可以直接管理几乎所有软件，却也导致在配置脚本时，必须打开对应软件界面进行配置，较为繁琐。为简化操作，AUTO-MAS 设计了「基础层-覆盖层」配置管理模型。

### 基础层 / 配置来源 | Base

一份配置的完整基础内容，配置的绝大部分信息都是直接来自于这份配置文件的。基础层必须打开对应软件界面才能配置，按存储位置，可以分成 3 类。

- **共享 | shared**

  存储在 `data/<托管 UUID>/Default` 目录下的配置文件，每个托管都允许存储一份托管级配置文件。直接配置外部软件时，该配置文件不会同步修改。其下属所有账号都可以直接使用该配作为其配置基础层，这份配置文件在托管下所有账号间共享。

- **独立 | independent**

  存储在 `data/<托管 UUID>/<账号 UUID>` 目录下的配置文件，每个账号都允许存储一份独立的配置文件。直接配置外部软件时，该配置文件不会同步修改。这份配置文件仅供该账号自己使用。

- **原生 | native**

  存储在外部软件内的配置文件，AUTO-MAS 不对其进行任何复制或独立存储。直接配置外部软件时，选择该配置来源的账号能够自动使用修改后的配置。

### 覆盖层 | Overlay

基础层决定了该软件的绝大部分配置内容，覆盖层则决定了该软件被高频修改部分的配置内容。覆写层可以直接在 AUTO-MAS 软件界面修改，按覆写程度分为 2 级。

- **覆写关键配置**

  仅覆写决定软件能否正常运行的关键配置，如：`启动时自动运行`

- **覆写常规配置**

  覆写软件高频修改的配置，如：`关卡配置`

## 游戏相关术语

### 游戏 | Game

AUTO-MAS 管理游戏运行环境的基本单位，例如一个安卓模拟器、一个 Windows 游戏客户端。

一个游戏对应一个受管理的运行环境，可以包含多个设备。

### 设备 | Device

任务可以选择并使用的具体运行目标。对安卓模拟器来说，一个设备对应一个模拟器多开实例；对 Windows 游戏启动器来说，一个设备对应一个游戏对象。

一个设备对应一个游戏对象，每个托管或账号均可以关联一个设备，一个设备可以被多个托管或账号绑定。
