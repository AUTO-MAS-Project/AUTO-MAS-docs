# 术语解释

在开始 AUTO-MAS 开发之前，建议先熟悉项目中的核心术语，以免阅读文档和协作沟通时产生歧义。

## 脚本相关术语

### 托管 | Script

AUTO-MAS 管理和调度外部脚本软件的基本单位。每个托管对应一个外部脚本软件，用于统一管理它的配置和运行信息。

一个托管对应一个外部脚本软件，下属可包含一个或多个账号。

### 账号 | User

AUTO-MAS 支持为同一个脚本保存多套配置，「账号」本质上就是脚本的某一套具体配置。由于一套配置通常对应一位用户或一个游戏账号，为便于日常交流，统一称为「账号」。

一个账号对应一套脚本配置，不再细分下级单位。

### 计划表 | Plan

计划表是一份可按周期轮换、供账号绑定的配置模板。在实际使用中，部分账号需要按星期切换不同设置，多个账号也可能需要同步调整同一项配置；通过绑定计划表，可以大幅减少重复修改的工作量。

一个账号最多绑定一张计划表，一张计划表可以被多个账号同时绑定。

## 配置相关术语

AUTO-MAS 采用直接管理外部脚本配置文件的方式来保存账号配置。这种设计能兼容绝大多数外部软件，但也意味着修改完整配置时往往需要打开原软件界面，操作较繁琐。为此，AUTO-MAS 引入了「基础层 + 覆盖层」的两层配置模型。

### 基础层 / 配置来源 | Base

提供一份配置的完整底稿，绝大多数选项都来自这里。基础层需要在外部软件自身界面中编辑，按存储位置分为 3 类：

- **共享 | shared**

  存放在 `data/<托管 UUID>/Default` 目录下的托管级配置文件。直接修改外部软件自身配置时，不会影响这里的副本；该托管下的所有账号都可以共享这份配置作为基础层。

- **独立 | independent**

  存放在 `data/<托管 UUID>/<账号 UUID>` 目录下的账号专属配置文件。直接修改外部软件自身配置时，不会影响这里的副本；该文件仅供对应账号单独使用。

- **原生 | native**

  直接指向外部软件自身的配置文件，AUTO-MAS 不做额外复制。选择原生来源的账号会自动使用你在外部软件中修改后的最新配置。

### 覆盖层 | Overlay

基础层决定软件的大部分默认配置，覆盖层则用于保存需要频繁调整的选项。覆盖层可以直接在 AUTO-MAS 界面中编辑，按覆盖范围分为 2 级：

- **覆盖关键配置**

  仅覆盖决定脚本能否正常联动运行的关键选项（例如「启动时自动运行」）。

- **覆盖常规配置**

  覆盖日常高频调整的业务选项（例如「关卡配置」）。

## 游戏相关术语

### 游戏 | Game

AUTO-MAS 管理的运行环境单位，例如一个安卓模拟器软件，或一个 Windows 游戏客户端。

一个游戏对应一个受管理的运行环境，可以包含多个设备。

### 设备 | Device

任务实际选中并使用的具体运行目标：对安卓模拟器而言，一个设备对应一个模拟器多开实例；对 Windows 游戏启动器而言，一个设备对应一个具体的游戏实例。

每个设备归属于一个游戏。托管或账号可以绑定一个设备，同一个设备也可以被多个托管或账号共享绑定。
