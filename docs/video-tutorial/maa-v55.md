# AUTO-MAS-Lite v5.5 部署 MAA（明日方舟）脚本图文教程

> 本文根据 2026-09-20 的完整部署录屏 `2026-09-20 22-19-54.mp4`（74 分钟，1920×1080）逐步整理而成，覆盖 **AUTO-MAS-Lite `v5.5.0-beta.6`** 从获取安装包到 MAA（明日方舟）脚本配置完成并成功拉起明日方舟的全流程。
> 所有截图均取自实际部署过程，**红圈 / 红框标注的就是该步骤中鼠标点击（或双击）的位置**。
>
> - **软件版本**：AUTO-MAS-Lite `v5.5.0-beta.6`，MAA `v6.18.0-beta.2`，MuMu 模拟器 12
> - **与 v5.4 的主要差异**：环境配置向导改为 4 步（运行环境 / 程序文件 / 依赖 / 启动）并新增镜像测速；MAA 的剿灭 / 日常任务改为在 AUTO-MAS 内**内联配置**（不再依赖 MAA 窗口勾选）；用户配置新增「配置管理方式」三模式；调度队列新增「队列类型 / 延时执行」；侧栏新增「游戏社区」。
> - v5.4 稳定版部署请看《[AUTO-MAS 部署 MAA（明日方舟）脚本图文教程](/docs/video-tutorial/maa)》。

**总流程一览**：获取 AUTO-MAS-Lite 安装包 → 安装 → 环境配置向导 → 导入模拟器 → 新建 MAA 脚本 → 配置任务（内联）→ 添加用户 → 配置 MAA 本体 → 运行验证 → 调度队列。

## 1. 准备工作

### 1.1 获取 AUTO-MAS-Lite 安装包

v5.5.0-beta.6 目前通过 **QQ 群「AUTO-MAS软件分发」的群文件**获取：`AUTO-MAS-Lite-Setup-v5.5.0-beta.6-x64.zip`（约 110 MB）。下载后得到：

![下载 AUTO-MAS-Lite 安装包](/docs/img/video-tutorial/v55-01-download.jpg)

同时确认以下前置条件（沿用此前部署）：

- MuMu 模拟器 12 已安装（本例 `E:/Games/MuMuPlayer`），模拟器内《明日方舟》可正常登录；
- MAA 已解压到 `D:\MAS\MAA-v6.17.5-win-x64`（含 `MAA.exe`）；
- 系统可解压 `.zip`。

### 1.2 解压并安装

1. 打开 `AUTO-MAS-Lite-Setup-v5.5.0-beta.6-x64.zip`，运行其中的 `AUTO-MAS-Setup.exe`；
2. 安装向导与 v5.4 相同：语言「简体中文」→ 同意协议 → 选择安装路径（本例 `D:\AUTO-MAS`）→ 安装；
3. **安装完成**页保持勾选「运行 AUTO-MAS」，**单击「完成」**：

![安装完成](/docs/img/video-tutorial/v55-02-install-done.jpg)

## 3. 首次启动：环境配置向导（v5.5 新版）

v5.5 的首次启动向导重新设计为 **4 步：运行环境 → 程序文件 → 依赖 → 启动**，全程自动：

### 3.1 镜像测速

向导首先对下载镜像测速（本例 gh-proxy（uv）0.38 MB/s），自动选择可用线路：

「依赖」阶段会一次性下载全部锁定版本的依赖包（约 136 MB，来源阿里云 / pypi 自动切换），耗时最长：

## 4. 新版界面总览

v5.5 主界面侧栏为：**主页、脚本管理、计划管理、模拟器管理、调度队列、调度中心**（底部：游戏社区、历史记录、工具、设置）。

- 「游戏社区」为 v5.5 新增入口，聚合官方 QQ 群、BUG 收集页等社区渠道；

## 5. 导入模拟器（MuMu）

1. **单击**左侧导航 **「模拟器管理」**；
2. **单击「🔍 自动搜索模拟器」**：

![v5.5 模拟器管理](/docs/img/video-tutorial/v55-05-emulator.jpg)

3. 与 v5.4 一样自动生成 MuMu 配置（路径 `E:/Games/MuMuPlayer/nx_main/MuMuManager.exe`、最大等待时间 300、强力关闭 关）。v5.5 新增了**设备列表**：显示设备序号（#0）、在线状态、名称与 **ADB 地址**（本例 `127.0.0.1:5555`），并可直接「显示 / 启动」设备。

## 6. 新建并配置 MAA 脚本

### 6.1 新建脚本

1. **单击**「脚本管理」→ **「+ 新建脚本」**；
2. 在「选择脚本类型」中**点选「MAA 脚本」**（v5.5 还新增了「MFW 脚本」类型，用于接入任意带 interface.json 的 MaaFramework 项目，见终末地教程）；
3. **单击「创建并配置」**：

![v5.5 新建脚本](/docs/img/video-tutorial/v55-06-newscript.jpg)

### 6.2 填写脚本配置

![v5.5 MAA 脚本配置](/docs/img/video-tutorial/v55-07-maa-config.jpg)

1. **基本信息**：脚本名称保持「MAA 脚本」；**MAA路径** **单击「选择文件夹」**，定位到 `D:\MAS\MAA-v6.17.5-win-x64`（含 `MAA.exe`）确认。
2. **模拟器管理**：模拟器选「MuMu模拟器」，模拟器实例按需选择。
3. **运行配置**（保持默认）：账号切换方法＝重启模拟器；用户单日代理次数上限 0；剿灭代理超时限制 40 分钟；日常代理超时限制 10 分钟；代理重试次数限制 3。
4. 保存。

## 7. 添加用户（内联任务配置）

1. 在「MAA 脚本」卡片上**单击「添加用户」**，填写用户名称、账号ID（官服填手机号后几位）、服务器等基本信息。
2. v5.5 的用户配置内置了完整的**任务配置**（是否启用快速配置 / 配置恢复开关在右上角），按「剿灭与日常分两次启动 MAA、组内按执行顺序排列」组织：

![v5.5 内联任务配置](/docs/img/video-tutorial/v55-08-user-tasks.jpg)

- **第一次启动 MAA：剿灭流程**——绿票商店（按需）、**剿灭作战**（显示"当前剿灭 · 周一组 本周未完成"）；
- **第二次启动 MAA：日常流程**——活动关卡优先、干员养成、**库存保持**（可添加预设/物品，设置目标库存，如 PR-A-1 医疗芯片 目标库存 20）、**理智作战**（关卡配置模式 固定、吃理智药数量、连战次数 AUTO、关卡选择 下拉里直接选 关卡-6/5、龙门币-6/5、红票-5 等）、**基建换班**（常规模式）、日常任务（自动公招 / 信用收支 / 领取奖励）、自动肉鸽等。

> ℹ️ 页面明确提示：**剿灭作战和日常任务会分别启动两次 MAA**——启用剿灭时先单独启动一次 MAA 执行剿灭，结束后再启动一次 MAA 执行日常流程。

3. **配置管理方式**（v5.5 新增三模式，红框区域）：

![配置管理方式](/docs/img/video-tutorial/v55-09-user-manage.jpg)

- **脚本**：使用脚本本级共享配置，所有用户共用；
- **用户**：使用当前用户独立配置，与脚本配置隔离；
- **直控**：直接使用 MAA 原有配置，由 MAA GUI 维护。

本例选择「脚本」+ 用户独立任务微调。保存用户。

## 8. 配置 MAA 本体（连接与接管）

1. 在「MAA 脚本」卡片上**单击「配置 MAA」**，AUTO-MAS 启动 MAA 窗口（本例为 MAA `v6.18.0-beta.2`）：

![v5.5 配置 MAA](/docs/img/video-tutorial/v55-10-maa-window.jpg)

2. 在 MAA「设置 → 连接设置」确认：连接配置＝MuMu 模拟器、连接地址 `127.0.0.1:16384`、ADB 路径 `E:\Games\MuMuPlayer\nx_main\adb.exe`、启用 MuMu 后端截图；
3. **注意**：使用内联任务配置后，AUTO-MAS 会接管 MAA 的任务列表（MAA 日志中会出现「已删除任务：剿灭作战 / 活动关卡优先」等记录，属于正常现象——执行时由 AUTO-MAS 按用户配置动态下发任务）；MAA 内只需确认连接方式，**不要点击 Link Start!**；
4. 进入「设置 → 启动设置」取消「开机自启动」，关闭 MAA 窗口，回到 AUTO-MAS **单击「保存配置」**。

在调度中心或卡片上启动后，AUTO-MAS 自动拉起 MuMu 模拟器并启动明日方舟：

## 11. 调度队列（v5.5 新增队列类型）

「调度队列」页面 v5.5 新增两个配置项：

- **队列类型**：定时队列（按定时表驱动）等；
- **延时执行**：到点后再延迟 N 分钟启动（错峰用）。

新建队列 → 设置启动时运行 / 定时运行 / 完成后操作 → 「添加定时」设置执行周期与时间 → 「添加任务」把 MAA 脚本加入队列，保存。用法与 v5.4 一致。

## 12. 常见问题与注意事项

| 现象 | 处理 |
| --- | --- |
| 环境向导卡在某一步 | v5.5 向导自动测速并切换镜像；可点「查看日志」观察，长时间无进展时重启 AUTO-MAS 重试 |
| MAA 窗口里任务列表被清空 / 出现"已删除任务" | 正常现象：v5.5 由 AUTO-MAS 内联任务配置接管，执行时动态下发任务 |
| 想完全用 MAA 自己的配置 | 用户配置的「配置管理方式」选「直控」，由 MAA GUI 维护 |
| 连接失败 | 确认 MuMu 12 已启动、连接配置＝MuMu 模拟器（127.0.0.1:16384）、设备列表中 ADB 地址可见、防火墙已放行 adb.exe |
| 剿灭显示"本周未完成" | 周一刷新剿灭次数，AUTO-MAS 会按周判断是否需要执行 |
