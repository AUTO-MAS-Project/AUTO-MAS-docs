# 桌面分身

桌面分身可以在独立的 Windows 桌面运行 PC 游戏和托管脚本。游戏画面在分身预览里，主桌面可以继续使用鼠标和键盘。此功能仍处于实验阶段，适用于 Windows 10 1809 及以上或 Windows 11 的 x64 桌面版。

以下界面和操作按 **v5.9.0-beta.1 后续 dev（be8ef6d5c）** 核对。

## 打开分身并运行任务

运行奇想盒时，请以管理员身份启动 AUTO-MAS。在此页选择奇想盒托管或队列，也可以在奇想盒编辑页的 **运行配置 → 执行会话** 选择 **桌面分身**。从主页或调度页手动单独启动该托管时会使用保存的选择。权限不足时保留原值，可重新以管理员身份启动，或在编辑页改选 **主会话**。

1. 打开 **设置 → 桌面分身**，选择要运行的托管或队列。队列中的托管都要支持分身，且队列的 **完成后操作** 要设为 **无操作**。模拟器任务请在主会话运行。各专项的要求见[桌面分身支持表](/docs/script-guide/#desktop-session)。
2. 分身分辨率默认是 **1920 × 1080**，也可以选择 **同步主屏分辨率**。最小化模式先用默认的 **后台最小化（推荐）**。
3. 点击 **打开分身并启动任务**。只想打开桌面时，清空任务选择，再点击 **打开桌面分身**。
4. 环境检测通过后，如果弹出 **验证 Windows 密码**，输入当前登录的 Windows 账户密码。检测或连接失败时，按下方对应提示处理。[环境检测](#environment-check) · [密码和连接](#authentication)
5. 派发后，在主窗口的 **调度** 页查看进度或停止任务。如果弹出 **确认任务分发**，先核对各队列或托管的运行位置。点击 **确认** 会按列表派发，点击 **仅运行桌面分身任务** 会跳过主会话列表中的项目。

常用的单个托管也可在托管编辑页将 **执行会话** 设为 **桌面分身**。这个选项用于手动单独启动该托管，队列和定时任务的运行位置不由它决定。

运行时可以点 **隐藏** 收起预览，分身保持连接。要操作分身时再点 **显示**。

## 环境检测异常 {#environment-check}

在分身窗口找到 **系统环境**，按显示的检测项处理。修完后回到分身窗口，点击 **重新检测环境**。

如果有 **尝试修复环境** 按钮，先查看弹窗列出的改动，再点击 **确认修复** 并通过 Windows 管理员授权。程序可以启用 Windows 子会话、启用本机远程桌面，以及启动远程桌面服务。服务被禁用时，程序会将它改成手动启动后再启动。复查通过后会保留这些设置。启用远程桌面后，现有防火墙和网络配置可能允许入站 RDP。

| 检测提示 | 处理方法 |
| --- | --- |
| 请使用 Windows x64，或请在已登录的交互桌面打开 MAS | 先登录 Windows，在桌面上打开 AUTO-MAS x64 桌面版。源码运行时也需使用 x64 Python。 |
| Windows 子会话未就绪，或本机设置关闭了远程桌面 | 优先使用 **尝试修复环境**。按钮未出现时，先处理列表里其他未通过的检测项，再重新检测。 |
| 组策略禁止远程桌面连接 | 在单位或学校的电脑上，请联系设备管理员确认是否允许远程桌面。 |
| 远程桌面服务或任务计划程序未运行 | 按 `Win + R`，输入 `services.msc`。找到 **远程桌面服务**（`TermService`）或 **任务计划程序**（`Schedule`），检查服务状态并启动对应服务。服务找不到、启动失败或设置受管控时，把服务名和 Windows 报错发给管理员。 |
| 找不到本机 RDP 监听，或本机 RDP 端口配置无效 | 先检查 **Windows 设置 → 系统 → 远程桌面** 和 **远程桌面服务**。如果电脑改过 RDP 端口，请让管理员检查本机端口配置。家庭版仅提示“未检测到普通 RDP 监听”时，仍可尝试连接。 |
| 远程桌面服务未使用原生 DLL | 如果安装过 RDP Wrapper 或修改过远程桌面组件，先按所用工具的卸载说明恢复 Windows 原生配置，再重新检测。 |
| 远程桌面服务未配置 ServiceDll | 请让设备管理员检查远程桌面服务配置，再重新检测。 |
| 找不到 `termsrv.dll`、无法确认文件签名，或无法加载 Windows 组件 | 用管理员身份打开命令提示符，依次运行 `DISM.exe /Online /Cleanup-image /Restorehealth` 和 `sfc /scannow`。完成后重启，再重新检测。[微软系统文件检查说明](https://support.microsoft.com/zh-cn/windows/experience/backup-recovery/using-system-file-checker-in-windows) |
| Windows PowerShell 签名验证未能运行 | 检查 Windows 自带的 **Windows PowerShell** 能否正常打开。如果被管理策略阻止，请联系设备管理员。 |
| 无法读取子会话开关或服务状态 | 在已登录的 Windows 桌面重开 AUTO-MAS，再检测一次。若仍失败，请导出或收集分身日志。[日志收集方法](#collect-logs) |

如果提示 **环境修复失败**、**修复后仍有检测项未通过** 或 **无法确认原设置已恢复**，点击 **导出分身日志**，把 ZIP 和完整报错一并反馈。修复后复查失败时，程序会尝试恢复原设置。如果提示无法确认恢复，请让管理员核对修复弹窗列出的设置。[日志收集方法](#collect-logs)

## 密码验证和远程桌面连接失败 {#authentication}

先在 **验证 Windows 密码** 窗口输入当前账户的实际密码。使用 PIN、指纹或人脸登录 Windows 的用户，也要填写账户密码。提示 **凭据所属账户与当前 Windows 账户不一致** 或 **无法解密保存的凭据** 时，请用当前账户的密码重新连接。

1. **本地账户**使用本机登录密码。账户只设过 PIN 时，先到 **Windows 设置 → 账户 → 登录选项** 确认是否已设置密码。
2. **微软账户**请先确认电脑已联网。若提示启用了仅允许 Windows Hello 登录，可到 **Windows 设置 → 账户 → 登录选项** 关闭该开关，确认能使用账户密码登录后再试。设置受管控时请联系设备管理员。[微软 Windows 登录选项说明](https://support.microsoft.com/zh-cn/accounts-billing/security/sign-in-options-in-windows)
3. 仍提示 **Windows 密码验证失败**、**远程桌面认证失败** 或 **远程桌面连接失败** 时，记下分身窗口显示的 **Windows 安全事件 4625** 时间、状态和子状态。窗口没有显示时，可按 `Win + R` 输入 `eventvwr.msc`，在 **Windows 日志 → 安全** 查找同一时间的事件 **4625**。[微软事件 4625 说明](https://learn.microsoft.com/windows/security/threat-protection/auditing/event-4625)

| 常见状态或子状态 | 处理方法 |
| --- | --- |
| `0xC000006A`（密码有误） | 核对当前账户的密码、键盘布局和大小写，再重新输入。 |
| `0xC0000234`（账户已锁定） | 暂停重试，先解锁账户。单位或学校账户请联系管理员。 |
| `0xC000015B`（账户缺少所需登录权限） | 请管理员核对当前账户的远程桌面登录权限。 |

提示 **密码已验证，但加密保存失败** 时，可继续本次连接，下次启动可能需要重新输入密码。Windows 家庭版提示 **子会话兼容性限制** 时，先按上面的步骤核对凭据和安全事件。确认没有认证问题后仍无法连接，可先在主会话运行任务，或考虑手动升级到 Windows 专业版。

## 任务派发、预览和关闭 {#task-errors}

| 现象 | 处理方法 |
| --- | --- |
| 队列无法选择，提示 **请将完成后操作设为无操作** | 打开该队列的配置，把 **完成后操作** 改为 **无操作**，再回到分身设置选择队列。 |
| 此托管或队列不支持桌面分身，或 **执行会话** 里没有分身 | 检查托管当前使用的控制器、启动方式和权限。队列里若混有不支持的托管，可把它们移到单独的主会话队列。[桌面分身支持表](/docs/script-guide/#desktop-session) |
| 队列或托管任务不存在 | 回到 **设置 → 桌面分身**，重新选择当前存在的队列或托管。 |
| 任务派发失败 | 点 **查看分身日志**，核对出错时间的日志，再到 **调度** 页查看任务是否已派发。[日志收集方法](#collect-logs) |
| 预览未响应、已退出、连接中断，或提示子会话已变化 | 重新打开分身，先确认 **调度** 页中的原任务状态，再重新运行需要重试的任务。 |
| 最小化后画面或脚本卡住，或子桌面分辨率和连接设置不一致 | 先点 **显示** 恢复预览。仍有问题时，在分身设置选择 **后台最小化（推荐）** 和 **1920 × 1080**，关闭后重新打开分身再试。 |
| 检测到已有 Windows 子会话 | 先确认是否由 BetterGI 等应用打开。需要复用时选择 **确认接管**。关闭接管的分身时可选 **仅断开连接**，这会停止 MAS 在分身中的任务，并保留分身里的其他程序。 |
| 关闭桌面分身失败 | 到主窗口的 **调度** 页检查任务是否结束，查看分身日志，再重试关闭。选择 **注销分身** 前，先保存分身中其他程序里正在编辑的内容。 |

## 收集分身日志 {#collect-logs}

环境修复报错时，优先点击分身窗口里的 **导出分身日志**。如果没有该按钮，点击 **查看分身日志** 打开目录，收集其中的 `host.log` 和 `control.log`。预览无法打开时，可从主窗口的 **设置 → 高级设置 → 导出日志压缩包** 收集程序日志。

反馈时附上 AUTO-MAS 版本、Windows 版本和版别、完整提示、出错步骤和时间。若问题出在派发，再附上托管类型、启动方式和队列的完成后操作。可以用 `winver` 查看 Windows 版本。发出前先遮去账号、本机路径等隐私信息。
